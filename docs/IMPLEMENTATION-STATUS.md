# 비전 어시스트 1.1.0 개발 미리보기

## 사용 가능한 준비 기능

- 기존 v1.0.11 흐름은 `실적 기반 입력 → 다른 작업 → 기존 방식으로 시작`에서 유지.
- 폴더 선택과 전용 XLSX 읽기. 원본 PDF/인보이스 자동 해석 기능은 아님.
- 직접 입력과 기본값 설정. 가공식품 신규용 제품유형·표시사항·제조공정·성분 편집 표.
- 폴더 내 사진/PDF 클릭: 한글표시 1, 전면 1, 기타 9. 기타 순서 변경.
- 작업 자료와 원본 첨부를 IndexedDB에 저장/복원/삭제. 외부 업로드 없음.
- 프로그램의 양식/지침 다운로드. 수식·매크로·외부 연결 XLSX는 거부.
- 실적 검색 기간 3개월 → 1년 → 3년. 전체 결과 건수/현재 목록 일치 시에만 최신 날짜 선택. 결과가 여러 페이지이거나 최신 날짜 동률이면 임의로 선택하지 않음.
- 원문에서 제품/화주/제조업소 등록번호를 확인. 읽을 수 있는 수량 단위·USD 값에 한해 개별/3개 값 적용.
- 준비된 단일 품목을 기존 검색·복사·화물·첨부/검증 흐름으로 전달. 같은 앱 탭/한 건에 묶인 자료만 사용.
- 신청인 연락처를 이번 건 값으로 전달. 기존 프로필 기본값을 조용히 덮어쓰지 않음.

## 신규 자동 입력: 미완료, 사용자 화면에서 실행하지 않음

현재 PC Chrome 연결 도구가 이 세션에 없으며, 로그인하지 않은 공개 신청서 URL은 HTTP 503을 반환했다. 매뉴얼과 스크린샷은 동적 DOM 계약을 대신하지 않는다.

`intake-runner.js`는 순서를 표현한 내부 개발 코드다. 실제 연결 미확인 항목이 있으므로 UI에서 import/실행하지 않는다. `신규 화면 연결 확인`은 입력값 변경 없이 구조를 읽고 준비 자료를 저장한다. 실제 입력 완료로 표시하지 않는다.

남은 실제 화면 연결 작업:

1. 신청서작성 메뉴 접근과 새 서식 생성 완료 대기, 제품구분 변경의 정확한 native confirm 문구.
2. 대행업체/화주/제조업소/창고/검사기관 조회창의 실제 입력 ID, 결과 행, 등록번호/명칭/부모창 결합 검증.
3. 신규 품목 편집 상태에서 HBL/연도 조회조건 입력 및 화물번호/MBL/HBL 3개 대조. 기존 cargoStep은 단일 기존 행을 전제로 하므로 신규용 계약이 별도로 필요.
4. 새 품목 추가 결과를 행별로 완전 대조(제품명·화물·수량·단위·중량·금액·기한), 대표품목 규칙, 여러 품목 합계 및 중단 후 결과 재대조.
5. 신고일반의 코드 조회·라디오·제품상태와 화주 휴대폰 연결. 현재 신규 runner는 이 모든 항목을 처리하지 않음.
6. 복합구성제품 실제 table ID와 자동 생성 행 식별, 공정 순서 및 중복 검증.
7. 성분 행의 실제 순번/상위순번 결합, 삽입 후 바뀐 행 위치 재읽기, 배합비 기준 검증과 주/부/혼합 구분. 배열 인덱스를 실제 부모행 순번으로 가정하면 안 됨.
8. 신규/여러 품목의 첨부 원본 해시 검증 및 오류검증·임시저장·전송을 기존 final-controller 수준의 문서 결합 보호로 연결.
9. 신규 pending 단계 복구: 실제 결과를 읽어 완료/미실행을 구분. 알 수 없는 결과를 재클릭하지 않음.

## 이번 검증 범위

- 모델: 양식 열/코드/성분 연결/비율/날짜/동일값 단위 보호/검색 기간.
- 실제 확장 테스트 브라우저: XLSX 읽기, 이미지/PDF 클릭 분류, 원본 File 저장/복원, 신규 DOM 문서 변경 시 쓰기 차단.
- 기존 회귀: 첨부 전달, 복사 결과 유실 복구, 메뉴 이동, 단일 품목 입력, 최종 동작 테스트.
- UNI-PASS 실서버 신규 입력/저장/전송은 검증하지 않았다.
- 메인/최신 릴리스는 변경하지 않으며 이 변경은 draft PR에서 검토한다.

## 재개에 필요한 자료

프로그램의 `진행 기록 → 신규 화면 연결 진단 → 기록 저장`은 input ID/type/label, 표의 ID/열 이름, 버튼 ID/이름을 기록한다. 값·비밀번호·인증서는 수집하지 않는다. 각 조회창의 구조도 같은 방식으로 수집 가능하다. 이 자료나 연결된 로컬 Chrome이 확보되면 1~9를 완성할 수 있다.
